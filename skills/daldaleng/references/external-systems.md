# 외부 서비스와 구축 당시 결정

외부 연동 문제는 달달영어 코드만으로 닫히지 않는다. 현재 API 계약/배포를 먼저 확인하고, 아래 티켓은 이유와 변경 경로를 찾는 근거로 사용한다.

## CMS와 뷰어

구축 #13(post 4128377455339810454)은 원천 리소스/메타를 CMS가, 커리큘럼 편성과 학습 이력을 LMS/달달영어가 관리하는 역할을 설명한다. 콘텐츠 리소스 동기화 성공과 회원 학습 편성 성공은 다르다.
구축 #56(post 4184990411148930313)은 viewer-container 메시지 정의의 원래 티켓. 현재 이벤트 계약은 front useViewerMessage와 API ContainerService를 대조한다.
구축 #70(post 4206112959987491462)의 CDN purge 가이드는 파일/폴더 단위를 요청한다. UI cache 문제라는 추측만으로 전체 /* purge를 실행하지 않는다.
원본/가이드 첨부는 이번 조사에서 다운로드하지 않았다.

## 회원·상품·자녀

구축 #92(post 4244068880593377099)의 1/13 답변은 최초 서비스 진입 시 회원 저장, 재로그인 시 회원 정보 갱신, gate→React→API 흐름을 설명한다. HTTPS 쿠키를 요청한 본문과 localStorage를 사용한다고 답한 댓글은 다르다. 실제 token 저장 방식은 현재 frontend useAxios/로그인 코드를 우선 확인한다.

플랫폼 #258(post 4285658574414042575)은 상품 코드가 모든 회원에게 같게 전달되던 문제를 거래/주문 식별자로 바꾸는 요청이다. 4/21 플랫폼 배포 댓글과 이후 달달영어 배포 후 확인 계획을 구분한다. 상품 번호·거래 번호·내부 회원 seq를 같은 키로 취급하지 않는다.

플랫폼 #401(post 4326269744173329637)은 달달영어→초코팝 이동 시 로그인과 선택 자녀가 바뀌는 문제다. 5/10 가이드는 redirect에 serviceCode=pop, URL encode한 path(맨 앞 / 제외), checkpoint=childSpecifiedSelect, cq1=자녀ID를 제시한다. 5/14 댓글은 달달영어의 5/13 운영 배포 후 종료한다. 실제 요청을 만들 때는 현재 caller/환경 URL을 재확인하고 실학생 token을 문서에 넣지 않는다.

## 배포 파이프라인

구축 #59(post 4189409844139685840), 2025-10-29 CodePipeline 안내:
- main push → 운영 pipeline
- staging push → 검증 pipeline
- develop 개발계 자동화는 개발업체 관리
- 서비스별 별도 repository, deploy/buildspec.yml·start_server.sh·stop_server.sh·appspec.yml 구성

현재 네 저장소 모두 위 deploy 파일과 Dockerfile이 존재하고 front에는 docker-compose.yml도 있다. 이 파일 존재가 현재 AWS pipeline trigger의 실측 증거는 아니다. **소스 저장소의 main/staging push는 단순 원격 백업으로 취급하지 않는다.** 배포 시점·현재 pipeline/branch 연결은 별도 확인한다.
이번 조사에서는 push/build/deploy/purge를 실행하지 않았다.
